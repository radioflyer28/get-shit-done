**Change 3 — extend handle-return step:**

After displaying the audit complete summary, parse `OUTPUT_PATH` (the SKILL-AUDIT.md just
written) and print a JSON object to stdout using the following schema (schema_version: "1.0"):

```json
{
  "schema_version": "1.0",
  "skill": "<SKILL_NAME>",
  "verdict": "<PASS|PASS WITH WARNINGS|FAIL>",
  "score": <smart_avg as float, or null if depth=quick>,

    {
      "area": "<structural|smart|prompt|tool>",
      "id": "<e.g. S-01, SMART-02, PQ-01, TU-01>",

      "issue": "<issue description text>",

    }
  ]
```

Parse the findings from the Remediation Plan table in SKILL-AUDIT.md. Derive `area` from the
`id` prefix: `S-` → `structural`, `SMART-` → `smart`, `PQ-` → `prompt`, `TU-` → `tool`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args → workflow | $ARGUMENTS contains user-controlled flag values; DEPTH and SKILL_NAME are untrusted input |
| workflow → tune-skill | OUTPUT_PATH (derived from user --output flag) is passed to tuner invocation |
| SKILL-AUDIT.md → JSON stdout | Audit findings parsed and re-serialized; content from audited skill files |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | parse-arguments: DEPTH value | mitigate | Validate DEPTH against exact set {quick,standard,deep}; reject with error message on invalid value |
| T-03-02 | Injection | handle-return: JSON serialization of SKILL-AUDIT.md content | mitigate | Use JSON.stringify (not string concatenation) for all JSON output — prevents JSON injection from adversarial finding text |
| T-03-03 | Tampering | handle-return: --fix routing with OUTPUT_PATH | accept | OUTPUT_PATH is derived from user's own --output flag and used within the same session; tuner (Phase 5) performs its own input validation |
| T-03-04 | Spoofing | parse-arguments: --structural-only + --depth both present | mitigate | --structural-only takes explicit precedence (sets DEPTH=quick regardless of --depth value) — documented in action, prevents ambiguous behavior |
</threat_model>
