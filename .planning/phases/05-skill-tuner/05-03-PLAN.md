  <action>
Extend the tune-skill workflow (created in Plan 05-01) with full batch and transcript functionality:

**Batch Mode Implementation (--batch FILE):**

1. **Load batch file** — Read JSON array from --batch file:
   ```json
   [
     { "skill": "gsd-auditor", "symptom": "Timeout on large input" },
     { "skill": "gsd-executor", "symptom": "Missing retry logic" },
     { "skill": "gsd-planner", "symptom": "Unclear error messages" }
   ]
   ```
   Validate: Each entry has "skill" and "symptom" fields; error if malformed

2. **Parallel audit invocation** — For each issue, invoke:
   ```bash
   gsd-audit-skill {skill}
   ```
   In parallel if possible, collect all SKILL-AUDIT.md outputs

3. **Generate all diffs upfront** — Loop through issues, invoke tuner agent for each with its symptom and audit findings. Collect all proposed diffs.

4. **Unified review gate** — Display ALL proposed diffs together (grouped by skill):
   ```
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   BATCH REVIEW: 3 skills, 5 proposed changes
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   
   [gsd-auditor]
   - Finding: Timeout handling
     Proposed: Add explicit error handler
   - Finding: Unclear error messages
     Proposed: Expand error text
   
   [gsd-executor]
   - Finding: Missing retry logic
     Proposed: Add exponential backoff
   
   [gsd-planner]
   - Finding: No validation strategy
     Proposed: Add Dimension 8 to checks
   
   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
   
   Approve all? (y/n/partial)
   ```

5. **Bulk approval** — User selects:
   - `y` — Apply all {N} diffs
   - `n` — Don't apply any
   - `partial` — Prompt for per-skill selection (e.g., "gsd-auditor: y, gsd-executor: n, gsd-planner: y")

6. **Atomic commit per batch** — After approval, apply all selected diffs and commit once:
   ```bash
   git add {all_modified_files}
   git commit -m "fix(batch): tune 2 skills — timeout handling + retry logic"
   ```
   Message format: `fix(batch): tune {count} skills — {comma-separated symptom themes}`

7. **Batch verification** — After commit, run `gsd-audit-skill {skill} --structural-only` for each skill; collect results in batch report

**Transcript Extraction Implementation (--transcript PATH):**

1. **Load transcript** — Read file from --transcript path (supports: text files, JSON logs, markdown)

2. **Extract friction signals** — Look for patterns:
   - Error keywords: "timeout", "fail", "error", "exception", "undefined", "null", "crash"
   - Performance keywords: "slow", "hang", "freeze", "unresponsive", "delay"
   - Clarity keywords: "unclear", "confusing", "ambiguous", "unexpected", "wrong"
   - User intent markers: "should", "must", "needs to", "always", "never"

3. **Augment symptom** — If --transcript provided, combine signals with direct symptom:
   ```
   User symptom: "Times out on large input"
   Extracted signals: ["timeout", "hang", "unresponsive", "needs retry"]
   
   Augmented symptom for semantic ranking:
   "Times out on large input. Session showed timeout errors, hanging behavior, 
   and unresponsiveness. Should implement retry logic for resilience."
   ```

4. **Size and safety caps**:
   - Truncate transcript to last 5000 characters (or N lines)
   - Warn user: "Transcript will be processed. Ensure no sensitive data included."
   - Don't log transcript content to commit messages

**Refinement in batch mode:**
- If user selects refinement on iteration 1, refinement applies to ALL remaining issues
- Example: "Expand context" refinement applies to all diffs not yet approved
- Document clearly which diffs were modified by refinement

Document all three modes in the workflow with clear examples.
