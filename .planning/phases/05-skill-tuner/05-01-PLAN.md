<task type="auto">
  <name>Task 2: Create tune-skill orchestration workflow</name>
  <files>get-shit-done/workflows/tune-skill.md</files>
  <action>
Create the tune-skill workflow with purpose section and 8+ named steps:

**Purpose:** Orchestrate human-in-the-loop skill tuning. Workflow: (1) collect symptom and flags, (2) invoke auditor for diagnosis, (3) prioritize findings by symptom relevance, (4) generate diffs, (5) present diffs to user, (6) handle refinement loop (up to 3 iterations), (7) apply approved diffs and commit, (8) verify no regressions.

**Available agents:** gsd-skill-tuner (created in Plan 05-02)

**8+ Named Steps:**

1. **Parse arguments** — Extract skill name, symptom (if provided), flags (--transcript, --dry-run, --batch)

2. **Intake symptom** — If no symptom provided inline, AskUserQuestion: "What issue should we fix?" (free-form narrative)

3. **Invoke auditor** — Run `gsd-audit-skill {skill}` to generate SKILL-AUDIT.md findings (skip if --dry-run and no user request)

4. **Load and prioritize findings** — Read SKILL-AUDIT.md, extract findings table; spawn tuner agent to semantically rank findings by symptom relevance

5. **Generate diffs** — Tuner agent proposes minimal, targeted changes for top-ranked findings with rationale linking to audit results

6. **Present diffs to user** — Display with syntax-highlighted inline edits (terminal color or markdown depending on runtime); show refinement options

7. **Refinement loop** — For up to 3 iterations: AskUserQuestion for Approve/Reject/Refine; if Refine, collect instruction (predefined menu OR free-form), pass to tuner, regenerate diffs, loop back to step 6

8. **Commit approved diffs** — Apply edits to skill files, commit with message `fix(skill): tune {skill-name} — {symptom-summary}`; if --batch, commit per batch: `fix(batch): tune {count} issues`

9. **Regression verification** — Run `gsd-audit-skill {skill} --structural-only` to confirm no regressions; display result to user

**Special handling:**

- **--dry-run flag:** Show all diffs without applying or committing; skip steps 7-8, end after step 6
- **--batch FILE:** Load issues from JSON array (each with skill + symptom); loop through all issues (steps 2-6 for each), collect all diffs, present unified review (step 5 consolidated), single approval gate, then apply all and commit batch atomically
- **--transcript PATH:** Extract friction signals from session file (look for error patterns, timeouts, "unexpected" keywords); use extracted signals as augmented symptom for finding prioritization

**Validation checks:**
- Skill exists: verify via `gsd-audit-skill --help` or file check
- Symptom non-empty: if user provides empty symptom in interactive mode, re-prompt
- Refinement max: counter increments each iteration; after iteration 3, gate with "Max refinements reached. Approve these diffs? (y/n/--force-override)"

Refer to workflow patterns in execute-phase.md and audit-skill.md for structure. Do NOT use heredocs.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User symptom input | User provides natural language describing skill problem — may be malicious or nonsensical |
| Audit findings | SKILL-AUDIT.md output from external auditor — must validate format before parsing |
| Session transcript | If --transcript used, transcript file may be large or contain sensitive info — validate and cap size |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | Proposed diffs | Mitigate | Validate all diffs before applying; require explicit user approval; diffs are surgical (not full rewrites) so blast radius is limited |
| T-05-02 | Spoofing | Auditor output (SKILL-AUDIT.md) | Mitigate | Validate SKILL-AUDIT.md format and structure before parsing; error if malformed |
| T-05-03 | Information Disclosure | Session transcript (--transcript flag) | Mitigate | Trim transcript to last N lines only; warn user about sensitive data; no logging of transcript content |
| T-05-04 | Denial of Service | Semantic analysis on huge audit findings | Mitigate | Cap findings to top 10-20 most relevant; timeout semantic analysis at 30s |
| T-05-05 | Elevation of Privilege | Refinement loop bypassing intent | Accept | User controls refinement; explicit gate at 3 iterations; --force-override requires conscious override |
| T-05-06 | Repudiation | Commit message ambiguity | Mitigate | Commit format is rigid: `fix(skill): tune {name} — {summary}`. Summary extracted from user's symptom and included for auditability |

</threat_model>
