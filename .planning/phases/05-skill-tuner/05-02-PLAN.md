**Input contract:**
```json
{
  "skill_name": "gsd-auditor",
  "skill_files_dir": ".planning/phases/05-skill-tuner/",
  "audit_findings_md_path": "{path_to_SKILL-AUDIT.md}",
  "symptom_description": "User's natural language description of the problem",
  "refinement_instruction": "[Optional] 'Expand context' or custom text for regeneration",
  "iteration_count": 1,
  "max_iterations": 3,
  "target_skill_path": "path/to/skill.md"
}
```

**Execution flow (5 steps):**

1. **Load and validate audit findings**
   - Read SKILL-AUDIT.md from path
   - Parse findings table (columns: Finding ID, Category, Severity, Description, Remediation)
   - Validate table structure; error if malformed

2. **Semantic prioritization of findings** (KEY: per D-02)
   - Input: symptom_description + audit findings table
   - Output: re-ranked findings sorted by relevance score
   - If NO refinement_instruction (initial generation):
     a. Extract key terms from symptom (tokenize, remove stopwords)
     b. Score each finding by keyword overlap + semantic affinity
     c. Compute similarity: (symptom, finding.description) using manual scoring (keywords + topic)
     d. Filter: keep findings with score >= 0.5
     e. Sort by score descending; top 3-5 findings become targets for diffs
   - If refinement_instruction provided:
     a. Parse instruction (match against preset list OR accept free-form)
     b. Focus diffs on findings that align with instruction intent
     c. Example: "Expand context" → prioritize findings about prompt clarity, examples, guardrails

3. **Generate candidate diffs**
   - For each top-ranked finding, identify which skill file(s) and lines need change
   - Generate minimal unified diff or inline edit proposal
   - Link each proposed change to the specific audit finding (create "Rationale" section)
   - Example:
     ```
     Finding #3: "Missing error handling for timeout case"
     
     File: agents/gsd-auditor.md
     Lines 245-250
     
     Current:
     ```bash
     timeout(COMMAND, 30s)
     ```
     
     Proposed:
     ```bash
     timeout(COMMAND, 30s) || {
       log "ERROR: Command exceeded 30s timeout"
       exit 1
     }
     ```
     
     Rationale: Audit finding suggests adding explicit error handling for edge cases.
     This change adds a timeout handler that logs and fails gracefully instead of silently timing out.
     ```

4. **Format diffs for presentation** (KEY: per D-03)
   - Determine runtime context: terminal (ANSI color), Copilot (markdown), etc.
   - If terminal: ANSI red/green highlighting for removal/addition
   - If markdown/Copilot: Inline markdown code blocks with emoji markers (🔴 removed, 🟢 added)
   - Fallback: Unified diff format if rendering fails
   - Include context lines around changes (not bare lines)

5. **Validate proposed diffs against SMART**
   - Read skill-smart-criteria.md
   - For each proposed change, check: Does it improve one SMART dimension without regressing others?
   - Dimensions:
     - **S (Specific):** Is the change concrete and actionable?
     - **M (Measurable):** Is success testable?
     - **A (Achievable):** Does tool permission alignment allow this change?
     - **R (Relevant):** Does the change address the reported symptom?
     - **T (Time-bound):** Are execution bounds clear?
   - Warn if any dimension appears to regress; surface to user

**Structured returns:**

Return `## TUNE COMPLETE` with:
- Proposed diffs (formatted per step 4)
- Iteration count and max (e.g., "Iteration 1 of 3")
- Rationale per diff (linking to audit findings)
- SMART validation summary per diff

Return `## TUNE BLOCKED` with:
- Reason (e.g., "SKILL-AUDIT.md malformed", "Zero findings match symptom", "All diffs would regress SMART dimensions")
- Suggestion for user (e.g., "Provide more specific symptom?", "Try different refinement?")

**Success criteria:**
- Diffs are generated and formatted per runtime
- All proposed changes are linked to specific audit findings
- SMART validation prevents regressions
- Refinement instructions regenerate without re-invoking auditor
- Syntax highlighting adapts to runtime context

**Anti-patterns to avoid:**
- Never re-analyze raw skill files (always use audit findings)
- Never include full file rewrites (surgical diffs only)
- Never present unlinked proposed changes (every diff has audit rationale)
- Never silently ignore SMART regressions (surface them to user)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Audit findings input (SKILL-AUDIT.md) | Read from external file — validate format before parsing |
| Symptom description | User input — may be malicious or excessively long — sanitize before embedding in prompts |
| Refinement instructions | User input — may attempt injection — validate against preset list or sanitize free-form text |
| Generated diffs | Code generation — must be validated for safety before presenting to user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Injection | Symptom description embedded in prompts | Mitigate | Sanitize symptom text; escape special chars; validate length (<500 chars) |
| T-05-02 | Tampering | Generated diffs | Mitigate | Diffs are surgical (not full file rewrites); every diff requires explicit user approval before applying |
| T-05-03 | Spoofing | Audit findings file (SKILL-AUDIT.md) | Mitigate | Validate file format and table structure before parsing; error if malformed |
| T-05-04 | Information Disclosure | Symptom analysis details | Accept | Agent logs reasoning; reasoning is shown to user for transparency |
| T-05-05 | Denial of Service | Semantic prioritization on huge findings set | Mitigate | Cap findings to top 10-20; timeout semantic scoring at 30s; fall back to string similarity if needed |
| T-05-06 | Elevation of Privilege | Refinement instructions bypassing SMART validation | Mitigate | Every refinement regenerates diffs; SMART validation runs on regenerated diffs too |

</threat_model>
