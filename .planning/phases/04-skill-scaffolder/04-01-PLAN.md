<threat_model>
**Threats addressed by this plan:**

1. **Path traversal via skill name (HIGH):**
   Skill name is used to construct file paths (`commands/gsd/{name}.md`). A name like `../../../etc/passwd` could write outside the intended directories.
   Mitigation: gather-inputs validates name against `^[a-z0-9][a-z0-9-]*$` and explicitly rejects `..`, `/`, `\`, spaces, `~` before any path construction.

2. **Prompt injection via description (MEDIUM):**
   User-provided description is inserted into generated SKILL.md files, which are themselves prompt files. Malicious descriptions could inject instructions into the generated skill.
   Mitigation: gsd-skill-scaffolder (04-02) sanitizes description by stripping XML tags and instruction-like patterns. The workflow also passes description through the scaffolder (not directly into files).

3. **File overwrite without confirmation (MEDIUM):**
   Silently overwriting existing skill files could destroy prior work.
   Mitigation: gather-inputs checks for existing files and requires explicit confirmation before overwriting.

4. **Agent context inflation via full agent file reads (LOW):**
   Reading full agent files during reuse check could inflate context cost or expose large agent internals unnecessarily.
   Mitigation: check-agent-reuse reads only `head -15` of each agent file — frontmatter only.

5. **Structural validation bypass (LOW):**
   Generated files that fail structural checks could be installed as broken skills.
   Mitigation: validate-output is non-optional; soft-warning pattern means validation failures are reported but user is always informed. Primary path uses the Phase 2/3 auditor for authoritative checks.
</threat_model>
