**## Frontmatter Field Reference**

**## Required Body Sections**
Table: Section | Tag | Description | Always required?
- Objective | `<objective>` | What the skill does, for whom, and what it produces | Yes
- Process | `<process>` | Step-by-step execution instructions | Yes

**## Optional Body Sections**
Table: Section | Tag | Description | When to include
- Execution Context | `<execution_context>` | @-path references to workflow/reference files the skill loads | When skill loads external files
- Runtime Note | `<runtime_note>` | Platform-specific behavior differences (Copilot vs Claude Code vs Gemini) | When behavior differs by platform
- Context | `<context>` | Variables, phase info, or data passed to the skill | When skill receives structured input

**## Platform Compatibility Matrix**
Table: Tool/Feature | Claude Code | Copilot (VS Code) | Gemini CLI | Notes
Cover key allowed-tools values observed in exemplar skills:
- Bash/shell commands — supported varies by platform (read exemplar runtime_note for specifics)
- Read, Write, Task — coverage status from exemplar `<runtime_note>` sections
- AskUserQuestion vs vscode_askquestions — platform-specific names
- Heredoc (`cat << 'EOF'`) — NEVER use in file-writing instructions (blocked on some platforms)
- `~/.claude/` paths — wrong on Copilot (use `~/.copilot/`) — note this explicitly

Extract actual platform notes from the exemplar skills' `<runtime_note>` sections. Do not invent compatibility data.

**## Anti-Patterns**
Table: Anti-Pattern | Why It Fails | Correct Alternative
Minimum 6 rows (extract from RESEARCH.md §Common Pitfalls and exemplar skills):
- Hardcoded `~/.claude/` paths → breaks on Copilot → use `~/.copilot/` or runtime-detected path
- `tools:` instead of `allowed-tools:` → agent-style frontmatter fails skill loading → use `allowed-tools:`
- Heredoc in file-write instructions → fails on some runtimes → use Write tool directly
- Ambiguous step verbs ("handle", "manage") → AI cannot determine what to do → use specific verbs with target and tool
- No completion marker → skill result undetectable → define `## DONE` output or named file
- Missing `<runtime_note>` for platform-specific behavior → silent failures on other runtimes → add runtime note with fallback
