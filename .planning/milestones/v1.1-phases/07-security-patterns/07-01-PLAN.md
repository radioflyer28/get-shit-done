**Create Pattern Loader Module** (`get-shit-done/bin/lib/pattern-loader.cjs`):

CommonJS module providing runtime access to pattern files. Exports:

1. **`loadPatternFile(language)`**
   - Takes language name (e.g., "python", "javascript", "go")
   - Returns parsed markdown file with OWASP sections
   - Returns object: `{ language, owasp_patterns: [], quick_reference: [...], semgrep_rules: [...] }`
   - Error handling: graceful fallback if file not found

2. **`loadSemgrepRules()`**
   - Loads and parses semgrep-rules-library.yml
   - Returns object with all rules indexed by rule ID
   - Validates YAML syntax
   - Returns: `{ semgrep_cli_version, community_ruleset_version, rules: { [id]: {...} } }`

3. **`getSemgrepRuleById(ruleId)`**
   - Looks up a specific rule in the library
   - Returns rule metadata: source, owasp, languages, confidence, false_positive_rate, description

4. **`generateGrepCommand(language, owasp_category)`**
   - Takes language + category (e.g., "python", "A03:2021-Injection")
   - Returns array of grep commands to run for that category
   - Used by pre-scan orchestrator to execute grep patterns

5. **`extractSemgrepRuleBlock(patternFile, ruleId)`**
   - Extracts the YAML rule block from a language pattern file
   - Returns rule in Semgrep format ready for --config input
   - Used to generate temporary semgrep config files during scanning

**Implementation notes:**
- Use stdlib only (require fs, path, yaml parsing via npm:yaml or hand-parse)
- All functions synchronous (to fit pre-scan orchestrator's constraints)
- Error handling: log to stderr, return empty defaults on failure
- Performance: cache parsed files in module scope to avoid re-reading

**Example usage** (pre-scan orchestrator):
```javascript
const loader = require('./lib/pattern-loader.cjs');
const patterns = loader.loadPatternFile('python');
const grepCmds = loader.generateGrepCommand('python', 'A03:2021-Injection');
// Execute grep commands in parallel...
```

## Trust Boundaries

| Boundary | Description | Threat |
|----------|-------------|--------|
| Pattern file → Agent context | Pattern definitions are loaded into agent prompt | Malicious rule could cause agent to misidentify safe code as vulnerable or vice versa |
| Semgrep rule version → Execution | Semgrep rules must be pinned to specific versions | Version mismatch could cause rule variance (same code, different findings) |
| Language file → Pre-scan orchestrator | Pattern files parsed and executed by orchestrator | Malicious pattern file could cause command injection in grep/semgrep execution |
| Pattern file sources → Security | Pattern definitions taken from semgrep.dev and manual creation | Community rules could include incorrect patterns; custom rules need validation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Spoofing | Pattern file identity | Mitigate | Verify all pattern files are in version control; require code review before commit. Validate file syntax (YAML/Markdown) before loading. |
| T-07-02 | Tampering | Semgrep rule modification | Mitigate | Version pin all semgrep CLI and community ruleset versions. Use checksums of rule YAML to detect tampering. |
| T-07-03 | Repudiation | Pattern source attribution | Accept | Pattern sources (semgrep.dev, manual) are documented in metadata. If community rule changes, new version gets new pin. |
| T-07-04 | Information Disclosure | Pattern reveals sensitive logic | Mitigate | Patterns describe only vulnerability signatures, not sensitive business logic. No secrets stored in pattern files. |
| T-07-05 | Denial of Service | Malformed pattern file crashes loader | Mitigate | pattern-loader.cjs has error handling for malformed YAML/Markdown. Graceful fallback if file not found. Unit tests validate syntax. |
| T-07-06 | Elevation of Privilege | Pattern allows agent to exceed authorization | Mitigate | Patterns are **read-only input** to agent context. Agent cannot execute arbitrary code via patterns. Patterns describe **detection rules**, not actions. |
| T-07-07 | Injection | Malicious grep command in pattern file | Mitigate | All grep patterns are manually reviewed and tested before commit. No dynamic command construction based on pattern content. Orchestrator escapes all inputs. |
| T-07-08 | Logic Error | Incorrect pattern matches wrong code | Mitigate | All patterns tested against real open-source projects (e.g., Django, Express, Go std library). False positive rates documented. Patterns reviewed by domain expert. |
| T-07-09 | Version Mismatch | Different semgrep version produces different rules | Mitigate | All semgrep rules pinned to specific CLI version (e.g., 1.45.0). Rules locked to community ruleset version. Orchestrator enforces version check before execution. |
| T-07-10 | Coverage Gap | Critical OWASP pattern missing | Mitigate | OWASP foundation document covers all 10 categories. Language files map each to language-specific pattern. Verification gate checks coverage before reporting. |
