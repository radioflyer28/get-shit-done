<objective>
Implement the Git Forensics Agent for Phase 9 of v1.1. Delivers a standalone git history analysis
workflow (`git-forensics.md`) backed by a bash shim (`git_forensics.sh`) and Python report builder
(`git_forensics_report.py`). The workflow detects supply chain attack indicators visible in git
history — binary blobs, force-pushed rewrites, `.gitattributes` execution vectors, and author
anomalies — then produces a structured `GIT-FORENSICS.md` report. The threat-scan workflow is
updated to invoke git forensics as an integrated optional step.

**Purpose:** Supply chain attacks leave traces in git history that static code analysis misses:
bulk-injected commits, an author appearing once to add a hook, or binaries smuggled via encoded
blobs. This phase adds timeline-aware forensics to the threat scanner.

**Output:**
- `get-shit-done/bin/git_forensics.sh` — standalone entry point (FOR-07)

- Updated `get-shit-done/workflows/threat-scan.md` — integrated invocation (FOR-07)
</objective>

Create `get-shit-done/bin/git_forensics.sh` as a bash script (~80 lines):

**Guard:** `git -C "$TARGET" rev-parse --is-inside-work-tree` or exit 1 with error message.

**Data collection phase** (store each to /tmp/gsd-forensics-$$/):
1. `git_log.txt` — `git -C "$TARGET" log --all --format="%H|%an|%ae|%ai|%s" 2>/dev/null`
2. `git_reflog.txt` — `git -C "$TARGET" reflog --all --format="%H|%gd|%gs|%ai" 2>/dev/null`
3. `git_branches.txt` — `git -C "$TARGET" branch -a --format="%(refname:short)|%(objectname:short)|%(authordate:iso)" 2>/dev/null`
4. `git_objects_binary.txt` — identify blobs: `git -C "$TARGET" cat-file --batch-all-objects --batch-check='%(objecttype) %(objectname) %(objectsize)' 2>/dev/null | awk '$1=="blob" && $3>0'`; for top 200 largest, run `git cat-file blob $sha | file - | grep -i "binary\|ELF\|PE32\|Mach-O\|archive\|compressed"` and output matching `sha|filename` pairs using `git log --all --find-object=$sha --format="%H %s"` to correlate commit.
5. `gitattributes.txt` — `find "$TARGET" -name ".gitattributes" -not -path "*/.git/*" -exec cat {} \; 2>/dev/null`
6. `git_hooks.txt` — `ls -la "$TARGET/.git/hooks/" 2>/dev/null | grep -v "^total\|\.sample$"`

**Invoke report builder:**
```bash
python3 "$(dirname "$0")/git_forensics_report.py" "$TARGET" /tmp/gsd-forensics-$$ "$OUTPUT"
```
where `$OUTPUT` defaults to `"$TARGET/GIT-FORENSICS.md"`.

**Trap cleanup:** `trap 'rm -rf /tmp/gsd-forensics-$$' EXIT`

Make executable. Do NOT use `set -e` — prefer explicit error handling per command.

<task type="auto" tdd="true">
  <name>Task 2: Python detection engine + GIT-FORENSICS.md report builder</name>
  <files>get-shit-done/bin/git_forensics_report.py</files>
  <behavior>
    - Binary blob detection: finds blobs matching binary file signatures, outputs blob sha + introducing commit + file path
    - History rewrite detection: parses reflog for "force update" entries, identifies commits present in reflog but absent from current branch tips (orphaned via rebase/amend), outputs sha|date|message for each
    - .gitattributes execution vector detection: flags lines matching smudge=, clean=, filter=, diff=, merge= that reference an external command
    - Author anomaly detection: flags (a) authors appearing in <3 commits who touched sensitive paths (hooks/, .github/, ci/, package.json, setup.py, Makefile, *.sh), (b) commits where timezone offset changed >6 hours from that author's baseline, (c) email/name mismatches for the same git config identity
    - GIT-FORENSICS.md produced with sections: Summary, Binary Blobs, History Rewrites, Attribute Execution Vectors, Author Anomalies, Raw Data
    - Each finding: severity (HIGH/MEDIUM/LOW), description, evidence (commit sha, file, timestamp)
  </behavior>
  <action>
Create `get-shit-done/bin/git_forensics_report.py` (~180 lines). Accepts args:
`python3 git_forensics_report.py <repo_path> <data_dir> <output_path>`

**Module structure (functions, not classes):**

`detect_binary_blobs(data_dir)` → list of `{sha, size, commit_sha, commit_subject, severity}`
- Parse `git_objects_binary.txt` (format: `sha|commit_sha commit_subject`)
- Severity: HIGH if size >100KB or commit_subject contains "update", "fix", "minor"; MEDIUM otherwise

`detect_history_rewrites(data_dir)` → list of `{sha, ref, action, date, severity}`
- Parse `git_reflog.txt`
- Flag entries where `$gs` (reflog subject) matches: `forced-update`, `rebase`, `amend`, `reset`
- Severity: HIGH for force updates on main/master; MEDIUM for others

`detect_attribute_vectors(data_dir)` → list of `{file, line, pattern, severity}`
- Parse `gitattributes.txt`
- Regex: `(smudge|clean|filter|diff|merge)\s*=\s*\S+` — flag any non-trivial RHS (not just `lfs`)
- Severity: HIGH if RHS contains shell metacharacters or absolute path; MEDIUM otherwise

`detect_author_anomalies(data_dir)` → list of `{author, email, commit_sha, reason, severity}`
- Parse `git_log.txt` (format: `hash|name|email|iso_date|subject`)
- Sensitive paths heuristic: check subject for keywords `hook`, `workflow`, `ci`, `pipeline`, `package`, `setup`, `makefile`, `deploy`
- Flag one-time authors on sensitive commits (author commit count < 3, subject matches)
- Flag timezone bursts: compute each author's median UTC offset from `%ai`; flag commits >6h deviation
- Severity: HIGH for one-time sensitive-path authors; MEDIUM for timezone anomalies

`render_report(findings_map, output_path)` → writes GIT-FORENSICS.md
- Header: `# GIT-FORENSICS Report`, repo path, date, summary table (finding category | count | highest severity)
- Section per category with findings as markdown table: `| Severity | Detail | Evidence |`
- Footer: `## Raw Data` section with truncated raw command outputs (first 50 lines each)
- If a section has 0 findings, write `✓ No issues detected in this category.`

`main()` → orchestrate all four detectors, call render_report, print summary to stdout.

<step name="run_git_forensics">
Run git forensics bash shim against target repo.

```bash
TARGET="${1:-$(pwd)}"
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/../bin" && pwd)"

if [ ! -d "$TARGET/.git" ]; then
  echo "⚠ Skipping git forensics: $TARGET is not a git repository"
  exit 0
fi

echo "Running git forensics on $TARGET..."
bash "$SCRIPT_DIR/git_forensics.sh" "$TARGET"

if [ -f "$TARGET/GIT-FORENSICS.md" ]; then
  echo "✓ GIT-FORENSICS.md produced"
else
  echo "✗ git forensics did not produce a report"
  exit 1
fi
```
</step>

<step name="review_findings">
Read and triage GIT-FORENSICS.md findings. For each HIGH severity finding:
- Binary blob: verify blob sha exists in current tree vs only in history (orphaned = less urgent)
- History rewrite: check if affected branch is main/master/release — flag if yes
- Attribute execution vector: read the actual filter command; flag if it runs arbitrary code
- Author anomaly: cross-reference with PRE-SCAN-RESULTS.json secret scanner findings for same commit

For MEDIUM findings: document but do not escalate unless corroborated by other findings.
</step>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → git_forensics.sh | Target repo path provided by caller — must be validated as git repo before any git commands |
| git object data → report | Raw git output (commit subjects, author names) is untrusted and must not be executed |
| GIT-FORENSICS.md → agent | Report content is attacker-controlled (commit messages, blob contents) — agent must treat as data, not instructions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | git_forensics.sh | mitigate | Validate `$TARGET` is inside a git worktree via `git rev-parse` before any operation; reject path traversal via absolute path resolution with `realpath` |
| T-09-02 | Information Disclosure | git_forensics_report.py | accept | Raw git output truncated to first 50 lines in report; no secrets extracted from blobs — only file type signatures via `file` command |
| T-09-03 | Elevation of Privilege | git_forensics.sh | mitigate | Script never executes any code from target repo; no `eval`, no sourcing of target files; `file` command used read-only |
| T-09-04 | Spoofing | Author anomaly detection | accept | Git commit metadata is not cryptographically verified by default; GPG-signed commits out of scope (FOR-05 specifies email/timezone heuristics only) |
| T-09-05 | Prompt Injection | GIT-FORENSICS.md → threat-scan agent | mitigate | GIT-FORENSICS.md content passed inside `<git_forensics>` XML tags — agent instructions state this is untrusted data to analyze, not instructions to follow |
</threat_model>
