Purpose: Foundation for all downstream phases (7–10). Deterministic pre-scan enables pattern libraries (SEED-007, SEED-008) and operational integration (SEED-010) to work with structured, reproducible data.

Output: Executable prescan.sh, prescan.py, tool registry, workflow updates, agent prompt updates. Phase 6 complete = Phase 7+ can parallelize.

Create bash shim that:
1. Detects runtime (Node → check package.json, Python → check requirements.txt, Go → check go.mod, Rust → check Cargo.toml, etc.)
2. Exports runtime context (PROJECT_TYPE, PYTHON_VERSION, NODE_VERSION, etc.)
3. Invokes Python orchestrator with current directory as target

Create Python orchestrator that:
1. Uses stdlib only (no external dependencies)
2. Imports tool registry from prescan-tool-registry.md
3. Filters applicable tools based on runtime detected
4. Executes each tool in parallel via concurrent.futures.ProcessPoolExecutor (default workers = cpu_count)
5. Captures stdout/stderr + exit code for each tool
6. Normalizes findings into unified JSON schema
7. Outputs PRE-SCAN-RESULTS.json to current directory

Python script structure:
- load_tool_registry() — Parse tool registry, return list of tools
- filter_tools(runtime) — Return tools applicable to detected runtime
- run_tool_parallel(tools) — Execute tools in parallel, collect results
- normalize_findings(raw_output) — Convert tool output to schema
- write_results(results) — Write PRE-SCAN-RESULTS.json

Bash shim: ~30–40 lines, simple and portable
Python orchestrator: ~150–200 lines, comprehensive but not over-engineered

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local → Tools | Pre-scan invokes local tools (npm audit, semgrep, etc.); untrusted tool output could be malformed JSON, missing fields, or extremely large |
| Tools → Prescan | Pre-scan must normalize malformed output gracefully (skip malformed findings, don't crash) |
| Prescan → Agent | Agent receives PRE-SCAN-RESULTS.json; must not blindly trust findings (false positives from tools) |
| Agent → Output | Agent produces security report; must clearly distinguish tool findings from agent reasoning |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | prescan.py execution | mitigate | Verify script permissions (execute-only, not writable), use absolute paths for tool invocation, no shell injection via tool arguments |
| T-06-02 | Spoofing | Tool output parsing | mitigate | Validate tool output structure (schema validation), handle missing/malformed fields gracefully, don't assume output format stability |
| T-06-03 | Repudiation | Tool invocation logging | mitigate | Log all tool executions to audit trail (which tools ran, exit codes, timestamp), included in PRE-SCAN-RESULTS.json |
| T-06-04 | Information Disclosure | Tool output sensitivity | accept | Pre-scan results may contain PII (file paths, secrets found by gitleaks); output goes only to local file + agent, not transmitted |
| T-06-05 | Denial of Service | Tool resource exhaustion | mitigate | Set timeout per tool (default 30s, configurable), kill runaway processes, handle concurrent.futures timeout gracefully |
| T-06-06 | Elevation | Local tool execution | accept | Pre-scan runs as current user (no privilege escalation), tool permissions unchanged |

</threat_model>
