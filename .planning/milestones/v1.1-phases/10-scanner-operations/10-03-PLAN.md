<objective>
**What:** Implement `supply_chain_intel.py` — a read-only CLI that queries three supply chain intelligence APIs (OSV, deps.dev, GitHub Advisory) in parallel for packages found in the project's lockfiles, producing `SUPPLY-CHAIN-INTEL.json`. Wire the step into `security-audit.md` so the agent receives package reputation context.

**Purpose:** Pre-scan orchestrator finds vulnerabilities in installed dependencies. Supply chain intel goes further: are these packages recently hijacked? Do they have known malicious versions? Are maintainers unusually inactive? OSV.dev and deps.dev provide this without requiring API keys. GitHub Advisory adds CVE-to-advisory cross-referencing.

**API details:**
- **OSV** (`https://api.osv.dev/v1/query`): POST `{package: {name, ecosystem}, version}` → returns `{vulns: [...]}`; public, no auth
- **deps.dev** (`https://api.deps.dev/v3alpha/systems/{ecosystem}/packages/{name}`): GET, no auth, returns metadata
- **GitHub Advisory** (`https://api.github.com/graphql`): POST GraphQL; requires `GITHUB_TOKEN` env var; gracefully skip if absent

**Output:**
- `supply_chain_intel.py` — parallel-query CLI
- `security-audit.md` — supply chain step wired in
</objective>

```graphql

  }
```

Lockfile parsing (packages to extract):
- package-lock.json: top-level "dependencies" keys + versions
- requirements.txt: each non-comment line → package name + version
- Cargo.lock: [[package]] name + version blocks
- go.sum: first field of each line (module@version)
- Gemfile.lock: DEPENDENCIES section
Limit to 50 packages per scan (highest severity first from pre-scan, or alphabetical if no prescan context).

Create `get-shit-done/bin/supply_chain_intel.py`. Stdlib only: `json`, `urllib.request`, `urllib.error`, `concurrent.futures`, `hashlib`, `argparse`, `sys`, `os`, `re`, `datetime`.

**Structure:**
1. `parse_lockfiles(target_dir)` → `list[{name, version, ecosystem}]` — scans for the 5 lockfile types above, returns up to 50 packages
2. `query_osv(pkg)` → `{vulns_count, vulns[], error}` — POST to OSV API, 5s timeout, catch `URLError`
3. `query_deps_dev(pkg)` → `{latest_version, license, error}` — GET deps.dev, 5s timeout, catch `URLError`
4. `query_github_advisory(pkg)` → `{advisories_count, advisories[], error}` — POST GraphQL if `GITHUB_TOKEN` set; return `{error: "GITHUB_TOKEN not set"}` if absent
5. `query_package(pkg)` → `{name, version, ecosystem, osv, deps_dev, github_advisory}` — calls all three, used as ThreadPoolExecutor worker
6. `main()` — argparse target_dir, calls `parse_lockfiles`, runs `query_package` in `ThreadPoolExecutor(max_workers=10)`, writes `SUPPLY-CHAIN-INTEL.json`

**Ecosystem mapping** for lockfile → API ecosystem name:
- package-lock.json / yarn.lock / pnpm-lock.yaml → `npm`
- requirements.txt / Pipfile.lock / poetry.lock → `PyPI`
- Cargo.lock → `crates.io`
- go.sum → `Go`
- Gemfile.lock → `RubyGems`

**Security:** All URLs are hardcoded constants (no user-controlled URL construction). All API responses parsed with `json.loads` (no eval). GITHUB_TOKEN sourced from env only.

**Error handling:** Each `query_*` function returns `{error: <str>}` on exception — never raises. `main()` proceeds even if all three APIs fail for a package.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External APIs (OSV, deps.dev, GitHub) → supply_chain_intel.py | Untrusted API responses; must parse as data, not execute |
| GITHUB_TOKEN env var → urllib Authorization header | Secret must not be logged or embedded in output file |
| Package names from lockfiles → API query parameters | Attacker-controlled package names in lockfile could craft URLs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-09 | Injection | Package name → API URL | mitigate | URL-encode package names using `urllib.parse.quote`; never use f-string directly in URL for user-controlled fields |
| T-10-10 | Info Disclosure | GITHUB_TOKEN in logs | mitigate | Never print GITHUB_TOKEN; only use in Authorization header. If error occurs, log "auth error" not the token value. |
| T-10-11 | Spoofing | API response tampering (MITM) | accept | HTTPS enforced by urllib default; no cert pinning needed for this developer-tool use case |
| T-10-12 | Denial of Service | Slow/hanging API responses | mitigate | 5-second timeout on all urllib calls; ThreadPoolExecutor bounded at 10 workers |
| T-10-13 | Info Disclosure | SUPPLY-CHAIN-INTEL.json in repo | accept | Contains only public package metadata; not sensitive. Document in .gitignore guidance. |
</threat_model>
