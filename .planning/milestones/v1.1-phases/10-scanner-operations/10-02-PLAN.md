<objective>
**What:** Implement baseline file support (`--baseline` flag, `.gsd-baseline.json`) and scan state tracking (`.gsd-scan-state.json`) that enables delta reporting — only new findings since last scan are surfaced to the agent.

**Purpose:** Production scanners accumulate accepted false positives. Without a baseline, every scan re-surfaces the same suppressed findings, creating alert fatigue. Without state tracking, CI pipelines can't distinguish "new issue introduced today" from "known issue we've already reviewed." OPS-02 and OPS-06 require both.

**Output:**
- `scan_baseline.py` — baseline load/apply/add-entry CLI
- `scan_state.py` — scan state read/write/delta CLI
- `security-audit.md` — `--baseline` flag + pre-agent baseline filtering + post-scan state update
</objective>

<!-- Schemas for baseline and state files -->

.gsd-baseline.json schema:
```json
{
  "version": "1",
  "entries": [
    {
      "hash": "<sha256 of rule_id+file+line>",
      "file": "src/app.py",
      "rule_id": "semgrep:python.lang.security.audit.eval-detected",
      "accepted_by": "alice",
      "accepted_at": "2026-04-15T10:00:00Z",
      "note": "eval used only in test harness, input is test-controlled"
    }
  ]
}
```

.gsd-scan-state.json schema:
```json
{
  "version": "1",
  "last_scan": {
    "scan_id": "abc12345-1713178800",
    "timestamp": "2026-04-15T10:00:00Z",
    "findings_hashes": ["sha256a", "sha256b"],
    "findings_count": 2
  }
}
```

PRE-SCAN-RESULTS.json findings structure (from Phase 6 / ORK-08):
```json
{
  "findings": [
    {
      "tool": "semgrep",
      "rule_id": "python.lang.security...",
      "file": "src/app.py",
      "line": 42,
      "severity": "ERROR",
      "message": "..."
    }
  ]
}
```

scan_baseline.py CLI interface (to implement):
  python3 scan_baseline.py apply <results.json> <baseline.json>  → prints filtered JSON to stdout
  python3 scan_baseline.py add   <results.json> <baseline.json> --hash <h> --by <user> --note <n>  → updates baseline
  python3 scan_baseline.py list  <baseline.json>  → prints table of accepted entries

scan_state.py CLI interface (to implement):
  python3 scan_state.py record <results.json> <state.json>   → writes state file
  python3 scan_state.py delta  <results.json> <state.json>   → prints delta JSON: {new: [], resolved: [], accepted: []}

  <behavior>
    - apply: finding with hash matching baseline entry → removed from output; finding without match → kept
    - apply: output JSON has same structure as input but filtered findings array
    - add: writes new entry to baseline.entries[]; idempotent (same hash twice = one entry)

    - list: prints tabular output of all accepted entries
    - missing baseline file → treat as empty baseline (no error)
  </behavior>
  <action>
Create `get-shit-done/bin/scan_baseline.py` with three subcommands (`apply`, `add`, `list`). Use stdlib only (json, hashlib, argparse, sys, os, datetime). No third-party deps.

`apply` subcommand:
- Loads PRE-SCAN-RESULTS.json and baseline file
- For each finding, compute hash = `hashlib.sha256(f"{finding['rule_id']}:{finding['file']}:{finding.get('line',0)}".encode()).hexdigest()`
- Filter out findings whose hash is in baseline entries
- Write filtered results to stdout as JSON
- Print suppressed count to stderr: `Baseline: suppressed N findings, N remaining`

`add` subcommand:
- Requires `--hash`, `--file`, `--rule-id`, `--by` args; `--note` optional
- Loads baseline (creates if missing), appends entry, writes back
- Sets `accepted_at` to current UTC ISO timestamp

`list` subcommand:
- Prints: hash[:8], file, rule_id, accepted_by, note — tab-separated
  </action>

  </verify>
  <done>apply filters findings matching baseline entries; add is idempotent; list prints accepted entries; all 3 subcommands exit 0</done>
</task>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| .gsd-baseline.json → scan_baseline.py | User-editable file; malformed JSON must not crash silently |
| PRE-SCAN-RESULTS.json → state delta | Finding hashes derived from tool output; hash collision is not a security vector here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-05 | Tampering | .gsd-baseline.json | mitigate | Validate JSON schema on load; reject entries missing required fields (hash, file, rule_id) |
| T-10-06 | Repudiation | Baseline add entries | mitigate | Record accepted_by and accepted_at; not cryptographically signed but provides audit trail |
| T-10-07 | Info Disclosure | .gsd-scan-state.json | accept | Contains only hashes and counts — no finding content. Low sensitivity. |
| T-10-08 | Denial of Service | Huge PRE-SCAN-RESULTS.json | accept | Solo dev workflow; file size is bounded by project scale |
</threat_model>
