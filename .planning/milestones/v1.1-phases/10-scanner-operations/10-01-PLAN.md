Create `get-shit-done/bin/scan_ci.sh` — a sourceable/callable helper that:

1. **Lockfile detection** — runs `git diff --name-only HEAD` (or `git diff --name-only HEAD~1 HEAD` in CI detached-HEAD mode as fallback) and greps for the 10 lockfile patterns above. Stores matches in `LOCKFILES_CHANGED` array.

2. **CI_MODE guard** — exports `CI_LOCKFILES_CHANGED` (space-separated list, empty if none changed).

3. **`write_ci_results` function** — accepts args: `scan_type` (security|threat), `findings_count` (int), `verdict` (string). Writes `CI_RESULTS.json` to `${TARGET_DIR:-$PWD}`. Uses `date -u +%Y-%m-%dT%H:%M:%SZ` for timestamp. `scan_id` = `$(git rev-parse --short HEAD 2>/dev/null || echo "no-git")-$(date +%s)`.

4. **Exit code convention** — exports `CI_EXIT_CODE`: 0 = clean/skipped, 1 = findings present, 2 = scan error.

Do NOT execute any scanning itself — this is a helper only. Chmod +x not needed (sourced or called via bash).

**CI execution branch** (insert after args parsed, before pre-scan step):

```bash
# CI mode: skip scan if no lockfiles changed
if [ "$CI_MODE" = "true" ]; then
  source "$(dirname "$0")/../bin/scan_ci.sh"
  detect_lockfile_changes "${ABS_TARGET}"
  if [ -z "$CI_LOCKFILES_CHANGED" ]; then
    echo "CI: No lockfile changes detected — skipping scan"
    write_ci_results "security" 0 "SKIPPED"
    exit 0
  fi
  echo "CI: Lockfile changes detected: $CI_LOCKFILES_CHANGED"
fi
```

**CI output at scan completion** (add to the verdict/output step for both workflows):

```bash
if [ "$CI_MODE" = "true" ]; then
  FINDINGS_COUNT=$(echo "$AGENT_OUTPUT" | grep -c "FINDING\|finding" || echo "0")
  if echo "$AGENT_OUTPUT" | grep -q "CLEAN\|no findings\|No findings"; then
    write_ci_results "security" 0 "CLEAN"
    exit 0
  else
    write_ci_results "security" "$FINDINGS_COUNT" "FINDINGS_PRESENT"
    exit 1
  fi
fi
```

For `threat-scan.md`, use `verdict` values: CLEAN, SUSPICIOUS, COMPROMISED (matching existing verdict strings from that workflow). For `security-audit.md`, use: CLEAN, FINDINGS_PRESENT.

The `--ci` flag MUST appear in the workflow's "Usage" or argument documentation block.

Do NOT change any non-CI execution paths. The only modification is: new flag in parser + new if-block in two locations per file.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI environment → scan_ci.sh | Git diff output passes through shell variable; attacker-controlled branch/commit names could inject |
| Agent output → CI_RESULTS.json | FINDINGS_COUNT derived from grep on agent output; must not execute agent output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | scan_ci.sh lockfile list | mitigate | Quote all variables: `"$CI_LOCKFILES_CHANGED"`. Never eval git output. |
| T-10-02 | Elevation of Privilege | CI_EXIT_CODE convention | accept | Exit codes are informational; CI system decides whether to block — acceptable. |
| T-10-03 | Spoofing | scan_id generation | accept | scan_id is for tracking, not auth; SHA8+epoch collision probability negligible. |
| T-10-04 | Injection | write_ci_results JSON values | mitigate | Use `printf '%s'` for string fields; avoid embedding raw agent output in JSON. |
</threat_model>
