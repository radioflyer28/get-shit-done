# Milestone v1.1: Security & Threat Scanner Tooling

**Status:** ✅ SHIPPED 2026-04-16
**Phases:** 6–10
**Total Plans:** 8

## Overview

Security and threat scanning operationalized through deterministic pre-scan orchestration, language-specific pattern libraries, supply chain git forensics, and CI-grade operational infrastructure. This milestone implements SEED-006 through SEED-010, transforming scanners from manual audit tools into continuous, production-grade security gates.

## Phases

### Phase 6: Pre-Scan Orchestrator

**Goal:** Hybrid bash/Python layer offloads ~60% of mechanical scanning work before agent involvement, reducing token costs and improving exhaustiveness.
**Depends on:** v1.0 foundation (workflows, agents)
**Plans:** 1 plan

Plans:
- [x] 06-01: Implement bash shim, Python orchestrator, tool registry, and workflow integration

**Details:**
- `security-prescan.sh` — bash shim with runtime detection (Node, Python, Go, Rust, Java, Docker)
- `security_prescan.py` — Python orchestrator using `ThreadPoolExecutor`, 30s per-tool timeout, stdlib-only
- `prescan-tool-registry.md` — 19 tools across 5 categories (dep scanners, secret scanners, SAST, IaC, binary/IOC)
- `PRE-SCAN-RESULTS.json` — unified normalized output schema
- `security-audit.md` and `threat-scan.md` updated to accept `<tool_findings>` from pre-scan
- Agent prompts shifted from "scan everything" to "analyze findings + reason about business logic"
- 28 integration tests (all ORK-01 to ORK-10 verified)

### Phase 8: Threat Adversarial Pattern Library

**Goal:** Dedicated semgrep ruleset for detecting deliberately malicious code — C2 beacons, obfuscated shells, logic bombs, supply chain hooks.
**Depends on:** Phase 7 (security patterns foundation)
**Plans:** 1 plan

Plans:
- [x] 08-01: Adversarial semgrep ruleset, test fixtures, validation suite, language reference threat sections

**Details:**
- `get-shit-done/semgrep/threat-patterns.yml` — 25 rules, 6 categories: `backdoor`, `exfil`, `supply_chain`, `logic_bomb`, `obfuscation`, `osint`
- All rules carry `metadata.category`, `metadata.severity`, `metadata.seed: SEED-008`

- 10 test fixtures (malicious + benign pairs for each category)

- `gsd-threat-scanner.md` updated with adversarial analysis mode
- THR-01 to THR-05 verified

### Phase 9: Git Forensics Agent

**Depends on:** Phase 8 (threat patterns)
**Plans:** 1 plan

Plans:

**Details:**

### Phase 10: Scanner Operational Excellence

**Goal:** CI integration, baseline mode, supply chain intelligence, formalized quarantine, and SBOM generation for production-grade automated scanning.
**Depends on:** Phases 6–9 (full scanner stack)
**Plans:** 4 plans

Plans:
- [x] 10-01: CI mode — `scan_ci.sh`, lockfile change detection, `CI_RESULTS.json` output

- [x] 10-03: Supply chain intelligence — `supply_chain_intel.py` with OSV, deps.dev, GitHub Advisory APIs

- `sbom_generate.sh` — syft/cyclonedx-cli wrapper for known-inventory SBOM

- `security-audit.md` and `threat-scan.md` updated with `--ci`, `--baseline`, `--sbom` flags

## Milestone Summary

**Total:** 5 phases, 8 plans, 22/22 requirements satisfied  
**Tests added:** 28 (Phase 6) + 77 (Phase 7) + ~20 (Phase 8) + 41 (Phase 9) + 71 (Phase 10) = ~237 new tests  
**Timeline:** 2026-04-15 → 2026-04-16

**Key Accomplishments:**
1. Pre-scan orchestrator offloads mechanical scanning — agents now reason about findings rather than re-scanning
2. 7 language-specific pattern files with OWASP Top 10 coverage and executable semgrep/grep patterns
3. 25-rule adversarial semgrep library covering 6 malicious code categories
4. Git forensics engine detecting supply chain attacks missed by surface-level analysis
5. CI-ready operational stack: baseline management, supply chain intelligence, SBOM generation, quarantine protocol

**Key Decisions:**

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Pre-scan orchestrator as v1.1 foundation | Solves token cost and coverage holistically | ✓ Shipped — significant agent cost reduction |
| Deterministic infrastructure over LLM variance | Mechanical scanning must be reproducible | ✓ All scans produce identical outputs for same input |
| Semgrep + community rules | Leverage battle-tested rulesets vs hand-crafted patterns | ✓ 25 adversarial + 27 OWASP rules from semgrep.dev |
| XML isolation tags for commit data | Prevent prompt injection when GIT-FORENSICS.md passed to AI agent | ✓ All forensics output wrapped in isolation tags |
| Median timezone baseline for anomaly detection | Median resists outlier influence better than mean | ✓ More reliable anomaly detection in irregular repos |
| stdlib-only for orchestrator and pattern loader | No external deps for security infrastructure | ✓ Zero new npm/pip dependencies added |

**Issues Deferred (v1.2):**
- External SBOM repository integration
- Telemetry-driven pattern quality scoring
- Automated remediation suggestions (detection only in v1.1)
- Multi-repo scanning orchestration
- Historical trend analysis and anomaly detection
